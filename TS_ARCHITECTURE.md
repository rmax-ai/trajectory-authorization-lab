# TS_ARCHITECTURE.md — Workspace Mechanics

## Workspace shape

`pnpm-workspace.yaml`:

```yaml
packages:
  - "apps/*"
  - "packages/*"
```

Five packages, internal scope `@tacl/*`:

| Package | Contents | Depends on |
|---|---|---|
| `@tacl/core` | events, graph, runtime, tools | — |
| `@tacl/authorization` | a0–a5 modules + policy registry | core |
| `@tacl/scenarios` | DSL types + scenario definitions | core |
| `@tacl/experiments` | runner CLI, metrics, report | core, authorization, scenarios |
| `@tacl/web` (apps/web) | Next.js inspection UI | core, scenarios (types only) |

Packages are **source-consumed** — no emit/build step for packages (tsx for the CLI, Next.js transpilePackages for the app, Vitest via Vite). `tsc --noEmit` is the type gate.

## tsconfig strategy (two root files)

- `tsconfig.base.json` — shared compiler options, `"composite": false`, strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.
- `tsconfig.json` — root, `"files": []`, `"references"` to each package's `tsconfig.json` (composite, `noEmit: false` + `emitDeclarationOnly` is NOT needed since no build — keep `noEmit: true` per package and skip composite references; the root tsconfig exists for the IDE and `pnpm typecheck` runs per-package `tsc --noEmit`).

Simplicity decision: **no project references**. Root `pnpm typecheck` = `pnpm -r --if-present run typecheck`. Each package has `tsconfig.json` extending `../../tsconfig.base.json` with its own `include`.

## Vitest workspace

`vitest.workspace.ts` at root with **explicit paths** (globs break tsconfig include):

```ts
export default [
  "packages/core/vitest.config.ts",
  "packages/authorization/vitest.config.ts",
  "packages/scenarios/vitest.config.ts",
  "packages/experiments/vitest.config.ts",
];
```

Each package config sets `test.name` and `environment: "node"` (web app is excluded from the workspace — it has its own tests only if added later).

## Next.js wiring (apps/web)

- `next.config.ts`: `transpilePackages: ["@tacl/core", "@tacl/scenarios"]` (anything imported as TS source).
- `.npmrc` root: `public-hoist-pattern[]=*react*`, `public-hoist-pattern[]=*react-dom*`, `public-hoist-pattern[]=*next*` — prevents duplicate React/Next instances in the workspace.
- Root `package.json` `pnpm.overrides` pins single React/Next versions across packages.
- The app reads run artifacts from `../../artifacts/` via a small server-side loader module — no bundling of artifacts at build time. `GET` only; it is a read-only inspector.
- Styling: minimal hand-written CSS (dark theme). No Tailwind, no component library — SPEC §13 prefers readability over polish.

## .npmrc

```
public-hoist-pattern[]=*react*
public-hoist-pattern[]=*react-dom*
public-hoist-pattern[]=*next*
```

## Adding a package

1. `packages/<name>/package.json` with `"name": "@tacl/<name>"`, `"private": true`, `"type": "module"`, `"exports": { ".": "./src/index.ts" }`.
2. Its `tsconfig.json` extends `../../tsconfig.base.json`.
3. Register in `vitest.workspace.ts` if it has tests.
4. Re-run `pnpm install` at root.

## Determinism & artifacts (SPEC §6)

- `artifacts/runs/<run-id>/` — `run.json`, `events.jsonl`, `graph.json`, `decisions.jsonl`, `metrics.json`.
- `artifacts/reports/latest.json|md` — regenerated by `pnpm experiment report`.
- `artifacts/` is gitignored except `.gitkeep`; runs are reproducible by re-execution, not by committing outputs.
